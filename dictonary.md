# Technical Specification: Supabase Dictionary Integration

Документация по структуре и интеграции облачного словаря для приложения.

## 1. Структура базы данных Supabase

Для работы словаря используется единая таблица `dictionary` в базе данных Supabase. 

* **Тип доступа:** Публичный (Row Level Security отключен для быстрого чтения с клиента).
* **Первичный ключ (PK):** `word` (уникальное слово).
* **Индексы:** Создан B-tree индекс `idx_dictionary_word` по полю `word` для мгновенного поиска и автодополнения (prefix search).

### Схема таблицы `dictionary`

| Колонка | Тип данных | Описание | Пример значения |
| :--- | :--- | :--- | :--- |
| `word` | `text` (PK) | Само слово или фраза | `"abduct"` |
| `ipa` | `text` | Международный фонетический алфавит (транскрипция) | `"/æbˈdʌkt/"` |
| `definitions` | `jsonb` | Массив строк с толкованиями (до 3 штук) | `["To take away by force; to carry away"]` |
| `synonyms` | `jsonb` | Массив строк с синонимами (может быть `null`) | `["kidnap", "captivate"]` |

## 2. Примеры запросов к Supabase (для фронтенда)

При интеграции на клиенте (через `@supabase/supabase-js`) используются следующие типовые паттерны:

### А. Поиск слова по точному совпадению (при клике или вводе)
```typescript
const { data, error } = await supabase
  .from('dictionary')
  .select('*')
  .eq('word', searchTerm.toLowerCase())
  .single();

Живой поиск / Автодополнение (Autocomplete / Search As You Type)
Быстрый поиск слов, начинающихся с введенных пользователем символов:
const { data, error } = await supabase
  .from('dictionary')
  .select('word, ipa, definitions')
  .ilike('word', `${query}%`)
  .limit(10);

Подробно о том, куда и как сохраняются слова пользователей:

1. Для зарегистрированных (авторизованных) пользователей
Слова сохраняются напрямую в базу данных Supabase в таблицу user_vocabulary.

Структура таблицы user_vocabulary в базе данных:
id (uuid) — уникальный идентификатор записи слова.
user_id (uuid) — id пользователя из таблицы auth.users (привязка слова к конкретному аккаунту).
word (text) — само английское слово или выражение.
ipa (text) — транскрипция (IPA).
definition (text) — определение на английском.
translation (text) — перевод слова.
synonyms (text) — синонимы.
notes (text) — личные заметки, примеры или мнемоники пользователя.
set_name (text) — название категории/набора (по умолчанию "General" или созданная пользователем категория).
status (text) — статус изучения: 'new', 'learning', 'learned'.
created_at / updated_at (timestamptz) — дата и время добавления/редактирования.
Безопасность (RLS): Для таблицы включен Row Level Security (RLS). Каждый пользователь видит, редактирует и удаляет только свои собственные слова (по правилу auth.uid() = user_id).

Категории/Наборы (Sets):
Созданные пользователем категории сохраняются в таблицу user_vocabulary_sets с привязкой к user_id.

2. Оптимистичный кэш и гостевой режим (LocalStorage)
Для обеспечения максимальной скорости работы интерфейса (без задержек сети при листании и поиске), а также для работы без авторизации:

Слова дублируются / сохраняются в локальное хранилище браузера localStorage под ключом:
javascript


localStorage.getItem("eng_tobe_my_vocabulary_words")
Категории сохраняются под ключом:
javascript


localStorage.getItem("eng_tobe_my_vocabulary_sets")
Настройки отображения карточек (чекбоксы видимости полей):
javascript


localStorage.getItem("eng_tobe_my_vocabulary_settings")
3. Как разделяются база dictionary и user_vocabulary:
dictionary (Облачный общий словарь) — это таблица со всеми готовыми словами, IPA и толкованиями, в которой происходит поиск 🔍 при вводе слова пользователем. Эта таблица доступна только для чтения.
user_vocabulary (Личный словарь пользователя) — сюда сохраняются слова конкретного пользователя (включая отредактированные поля, перевод, категорию и статус изучения).
4. Где находится SQL-миграция для создания этих таблиц в Supabase:
Файл миграции создан в проекте:

supabase/migrations/20261001_user_vocabulary.sql
Если вы еще не применяли этот SQL в панели Supabase SQL Editor, его достаточно один раз выполнить, чтобы таблицы user_vocabulary и user_vocabulary_sets были созданы в вашей базе.
